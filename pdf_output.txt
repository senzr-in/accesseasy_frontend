This document provides a set of interfaces for direct access to access control devices. After purchasing the
equipment, users can directly develop a complete access control or related application system based on the
interface speciﬁcations. The interface uses the MQTT communication protocol and can interface with various
common MQTT brokers; however, we recommend using an access control gateway for uniﬁed device
management.
The interface uses the MQTT protocol, and is divided into uplink and downlink in terms of direction:
Based on the initiator, they are divided into: command-type and event-type.
The message format is a standard MQTT message structure, containing a message topic and message
content, as follows:
I. Overview
Application scenarios
Interface Speciﬁcation
Uplink : refers to the device sending a message to the background or application.
▸
Downlink : refers to the process of sending a message from the background or application to the device.
▸
Command-type commands are initiated by the application platform. First, a downlink is sent to the device,
followed by an uplink , where the device returns the command to the application platform.
▸
Event-based : This is initiated by the device itself. First , it uploads data to the platform application, then it
downloads data back to the device , and the platform application sends a response back to the device.
▸
1. Message Topic: The message title, whether for uplink or downlink, the basic rule for sending and returning
commands is the command name followed by the command_reply . The format is as follows:
Downlink: access_device/v1/cmd/{#uuid}/xxxx, corresponding return command (uplink):
access_device/v1/cmd/xxxx_reply
▸
Uplink: access_device/v1/event/yyyy, corresponding return command (downlink):
access_device/v1/event/{#uuid}/yyyy_reply
▸
Note: `access` is a speciﬁc identiﬁer for the access control system; `cmd` indicates that the
backend or application actively sends a command to the device; `event` indicates that the device
actively sends a message to the backend or application or triggers an event; `{#uuid}` represents
the device's unique identiﬁer.
